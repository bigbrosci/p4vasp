# p4vasp fixes — 2026-10-12

## English

### Build panel: table and text views stay exclusive

- Fixed the Build panel showing both the coordinate table and POSCAR text editor while **text** was selected, as reported when enlarging the interface.
- Reproduced the overlap by selecting text mode and calling the parent widget's `show_all()` during a resize/refresh. Only the text editor was protected from recursive show calls, so the hidden table editor became visible again.
- Set `no_show_all` on both editor containers in `lib/p4vasp/applet/BuilderApplet.py`. The table/text radio buttons now explicitly control which editor is visible, including after parent refreshes. The initial view remains the table.
- Added a regression test in `test/testGtk3.py` covering the initial state, repeated view switching, resizing, parent `show_all()` calls, editor visibility and allocation, and visibility of the selective-dynamics control.
- Restart p4vasp from the updated checkout to load the fix.

### Verification and remaining issues

- Focused GTK regression test passed at **800 × 600**, **1400 × 900**, and **900 × 650** window sizes. Rendered table and text views were also captured and inspected at **1400 × 850**; only the selected editor was displayed.
- Bundled test suite: **57 tests passed**. GTK applet startup checks: **31 passed, 0 failed**. `git diff --check` passed.
- The full GTK regression suite did not pass: resource-loading checks reported separate Glade property-conversion errors, including shadow types, window hints, gravity, and text wrapping.
- Testing with a synthetic POSCAR also exposed a separate live-parsing error during text-buffer replacement involving `ParseException`. The focused layout regression isolates parsing to test view visibility; it does not validate POSCAR editing. These parsing and resource-conversion issues were not changed by this fix.

### Automatic log-file writing disabled

- Commented out both `FrameMessageDriver(xml,"p4vasp.log")` setup calls in `p4v.py` and replaced them with `FrameMessageDriver(xml)`, which uses the existing `DummyFile` logger. The GUI no longer automatically creates or writes `p4vasp.log`; interface status and error messages remain active.
- The original file-logging calls remain as comments. To re-enable logging, restore those calls in place of the no-file calls. Existing log files are not deleted. Restart p4vasp to apply the change.
- Verification: Python syntax and both logger call sites were checked; the dummy logger's write, flush, and close operations were checked with file opening blocked. `git diff --check` passed. The GUI and full test suites were not rerun for this logging change.

### Shift + left-drag atom selection

- Added rectangular selection in the native FLTK/OpenGL structure window: hold **Shift**, drag with the **left mouse button**, and release to add atoms to the current selection. A cyan rectangle with a dark outline shows the region while dragging. Repeated selection does not duplicate or deselect atoms; the existing clear-selection action starts a fresh selection.
- Selection uses atom-center screen projections, including atoms behind other atoms. Explicitly hidden atoms and centers outside the view/clipping range are excluded. Periodic replicas retain their atom/image identities. This supports the workflow **Side view → Shift + left drag → select a layer** without adding a mode button.
- Plain left drag still rotates, and cursor + Space still toggles individual atoms. **Esc** cancels a box gesture; tiny drags do nothing. Losing focus, hiding the window, or resizing during the gesture cancels it. Releasing Shift before the mouse button does not change the gesture into rotation.
- Implemented in `src/VisStructureDrawer.cpp` and its header, with priority event dispatch and final overlay drawing in `src/VisWindow.cpp`. `src/VisFLWindow.cpp` now returns handled events correctly, preventing a consumed Escape from reaching window shortcuts. One selection notification per completed box uses the existing Python selection synchronization.
- Rebuilt the Python 3 native extension locally. Restart p4vasp to load it; other checkouts must rebuild with `bash install/build-ubuntu-py3.sh` before launching.
- Verification: `test/run_box_selection.py` compiled and ran the native FLTK/OpenGL regression using synthetic input events and a synthetic structure. It covered overlapping front/back atoms, hidden atoms, additive selection, duplicates, reversed/empty/tiny rectangles, periodic replicas, Side view, perspective/zoom, resize, focus loss, Esc, Space, ordinary rotation, and a single batch notification. Drag and selected-state renderings were captured and inspected. This is not a manual end-to-end test of every selection-dependent applet.
- After rebuilding: **57 bundled tests passed** and **31 GTK applet startup checks passed**. The full GTK suite ran 8 tests and reported the **14 previously observed resource-property subtest failures**. `git diff --check` passed. macOS and HiDPI displays were not tested.

### Shift + 左键拖动框选原子

- 在原生 FLTK/OpenGL 结构窗口中新增矩形框选：按住 **Shift**，用**鼠标左键拖动**，松开后将区域内的原子追加到当前选择。拖动时显示带深色外边的青色矩形。重复框选不会重复添加或取消原子；需要重新选择时使用已有的清空选择功能。
- 按原子中心在屏幕上的投影判断是否入框，包括被其他原子遮挡的原子；主动隐藏的原子及中心位于视图／裁剪范围外的原子不选。保留周期复制原子的索引与镜像标识。可直接按 **Side view → Shift + 左键拖动 → 选中某一层** 的流程操作，无需增加模式按钮。
- 普通左键拖动仍用于旋转，光标 + Space 仍用于单原子选中／取消。**Esc** 取消当前框选，微小拖动不触发选择；拖动期间窗口失去焦点、隐藏或改变尺寸也会取消。先松开 Shift 再松开鼠标，不会中途变成旋转。
- 框选逻辑位于 `src/VisStructureDrawer.cpp` 及其头文件；`src/VisWindow.cpp` 负责优先分发框选事件并最后绘制矩形。`src/VisFLWindow.cpp` 正确返回已处理事件，避免用于取消框选的 Escape 继续触发窗口快捷键。每次有效追加只发送一次选择通知，复用现有 Python 选择同步机制。
- 已在本机重新编译 Python 3 原生扩展，重启 p4vasp 后生效。其他项目副本需先执行 `bash install/build-ubuntu-py3.sh` 重新编译。
