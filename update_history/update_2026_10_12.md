# p4vasp fixes — 2026-10-12

## English

### Build panel: table and text views stay exclusive

- Fixed the Build panel showing both the coordinate table and POSCAR text editor while **text** was selected, as reported when enlarging the interface.
- Reproduced the overlap by selecting text mode and calling the parent widget's `show_all()` during a resize/refresh. Only the text editor was protected from recursive show calls, so the hidden table editor became visible again.
- Set `no_show_all` on both editor containers in `lib/p4vasp/applet/BuilderApplet.py`. The table/text radio buttons now explicitly control which editor is visible, including after parent refreshes. The initial view remains the table.
- Added a regression test in `test/testGtk3.py` covering the initial state, repeated view switching, resizing, parent `show_all()` calls, editor visibility and allocation, and visibility of the selective-dynamics control.
- Restart p4vasp from the updated checkout to load the fix.

### Verification and remaining issues

- Focused GTK regression test passed at **800 × 600**, **1400 × 900**, and **900 × 650** window sizes. Rendered table and text views were also captured and inspected at **1400 × 850**; only the selected editor was displayed.
- Bundled test suite: **57 tests passed**. GTK applet startup checks: **31 passed, 0 failed**. `git diff --check` passed.
- The full GTK regression suite did not pass: resource-loading checks reported separate Glade property-conversion errors, including shadow types, window hints, gravity, and text wrapping.
- Testing with a synthetic POSCAR also exposed a separate live-parsing error during text-buffer replacement involving `ParseException`. The focused layout regression isolates parsing to test view visibility; it does not validate POSCAR editing. These parsing and resource-conversion issues were not changed by this fix.

### Automatic log-file writing disabled

- Commented out both `FrameMessageDriver(xml,"p4vasp.log")` setup calls in `p4v.py` and replaced them with `FrameMessageDriver(xml)`, which uses the existing `DummyFile` logger. The GUI no longer automatically creates or writes `p4vasp.log`; interface status and error messages remain active.
- The original file-logging calls remain as comments. To re-enable logging, restore those calls in place of the no-file calls. Existing log files are not deleted. Restart p4vasp to apply the change.
- Verification: Python syntax and both logger call sites were checked; the dummy logger's write, flush, and close operations were checked with file opening blocked. `git diff --check` passed. The GUI and full test suites were not rerun for this logging change.

## 中文

- 通过切换到文本模式，并在调整窗口尺寸／刷新时调用父控件的 `show_all()`，成功复现问题。此前只有文本编辑器受到递归显示保护，隐藏的表格编辑器会被再次显示。
- 在 `lib/p4vasp/applet/BuilderApplet.py` 中，为两个编辑器容器都设置 `no_show_all`。现在由 table/text 单选按钮明确控制显示哪个编辑器，父控件刷新后也能保持所选视图。初始视图仍为表格。
- 在 `test/testGtk3.py` 中新增回归测试，覆盖初始状态、反复切换视图、调整窗口尺寸、父控件调用 `show_all()`、编辑器的可见性和尺寸分配，以及选择性动力学控件的可见性。
- 从更新后的项目目录重新启动 p4vasp，即可加载修复。

### 验证结果与剩余问题

- GTK 专项回归测试在 **800 × 600**、**1400 × 900** 和 **900 × 650** 三种窗口尺寸下通过。同时捕获并检查了 **1400 × 850** 尺寸下的表格和文本视图，确认只显示所选编辑器。
- 内置测试套件：**57 个测试通过**。GTK 小程序启动检查：**31 个通过，0 个失败**。`git diff --check` 通过。

### 禁用自动日志文件写入

- 原文件日志调用以注释形式保留。如需重新启用日志，可用原调用替换对应的无文件日志调用。已有日志文件不会被删除；重新启动 p4vasp 后生效。
- 验证：已检查 Python 语法及两处日志初始化调用，并在禁止打开文件的条件下检查空日志对象的写入、刷新和关闭操作。`git diff --check` 通过。本次日志调整未重新运行 GUI 和完整测试套件。
