## English

### ASE-backed bulk modeling inside Models

- The user explicitly selected the first scope: bulk crystal types, lattice parameters, supercells, preview and POSCAR saving. Replaced only the empty bulk tab with a scrolling GTK page; surface remains a placeholder. Existing Models toolbar binding, models.glade host and GTK3 adapter remain the navigation/layout chain.
- Actual geometry comes from ASE `ase.build.bulk` and crystal repetition. Offered 13 tested prototypes: sc, fcc, bcc, diamond, hcp, bct, rocksalt, zincblende, cesiumchloride, fluorite, wurtzite, orthorhombic and rhombohedral. Explicit active lattice parameters, primitive/orthorhombic/cubic cell requests and three basis-direction repeat counts are validated. Unsupported combinations show errors instead of substituting a cell. Some prototypes depend on ASE reference bases; this is not arbitrary compound/space-group construction.
- The initial Cu/fcc/a=3.615 Å is an editable example, not a relaxed material property. Reject invalid elements/formula units, nonfinite/nonpositive lengths, invalid angles/internal coordinates/repeats, degenerate cells and supercells over 10000 atoms before replication. Oversized formula counts are rejected before ASE can expand them. Parameter edits invalidate the previous result and disable preview/save until rebuilding.

### Isolated optional ASE environment and worker

- Added install/install-ase.sh to create .venv-ase with tested ASE 3.29.0; the environment is gitignored. Installed it on this Linux device without changing the GUI interpreter or its NumPy. P4VASP_ASE_PYTHON may select an existing compatible interpreter.
- ase_bulk.py starts one short-lived worker only on Build bulk. The GUI thread remains responsive; numerical thread counts are limited, cancellation and a default 30-second timeout terminate/reap the child, and page destruction cancels pending work. Missing dependencies produce installation guidance; opening Models does not import ASE in the GUI process or start a worker.
- No Windows rebuild, ASE/RDKit bundling or macOS runtime acceptance was performed. Existing portable Windows packages do not contain this new implementation.

### Native preview and POSCAR saving

- Reused the session-owned auxiliary native window and event protection from gas_phase.py through show_model_preview. Bulk uses normal element display data; gas preview retains its covalent radii/bond factor. Title and display settings are switched explicitly. Native preview events are consumed without changing the currently loaded system.
- Reused InputFolderDialog with an optional action label. Save POSCAR creates a new folder containing only the generated POSCAR, with existing-folder protection, cancellation and visible write errors. The file uses sorted element groups and Direct coordinates; no INCAR/KPOINTS/POTCAR, initial moments or fixed-atom constraints are generated. Reopen the saved POSCAR to edit through existing tools. Preview/save use the same generated geometry; page results remain in memory until saved.
