# p4vasp update — 2026-11-06

## English

### Report and reproduced plot-refresh error

- The user reported that `p4v &`, `p4v DOSCAR` and `p4v vasprun.xml` initially displayed DOS, but switching to another panel and returning to DOS+bands left it blank. Loading DOSCAR or vasprun.xml through File/Open also failed to display DOS.
- Traced frame.glade DOS+bands toolbar → p4v.startApplet/showApplet → ElectronicApplet's graphwindowapplet.glade → GraphCanvas and its GTK3/Cairo adapter. File-menu/Open actions share load_system_selected/getSystem and system activation.
- A real Frame/startApplet synthetic-data reproduction raised AttributeError in GraphCanvas.updateSize: GTK3's Gdk.Window has no get_size. This interrupted the scheduled DOS redraw. Changed it to use the drawing area's allocated width/height, bounded to at least one pixel; it also works before a native window is realized. No rendering backend or applet-destruction redesign was introduced.

### Standalone DOSCAR loading and total-DOS parsing

- getSystem previously routed every non-XML file, including DOSCAR, through PoscarSystemPM. Added explicit, case-insensitive DOSCAR filename dispatch to DoscarSystemPM. It reads the selected file, total DOS and header Fermi energy directly. POSCAR/CONTCAR and INCAR are optional; DOS data is not treated as atomic coordinates.
- readDOSCAR now respects the header's NEDOS count. Three-column rows form one channel; five-column spin-polarized rows form separate up/down energy/density/integrated channels. Later projected-DOS blocks are excluded from TOTAL_DOS. Invalid headers, truncated rows and inconsistent columns fail rather than creating synthetic data. Reader-owned files are closed on both success and failure.
- Original densities remain unchanged. ElectronicApplet retains its existing E−E_Fermi energy reference and negative plotting convention for the down-spin channel. A standalone DOSCAR does not supply band eigenvalues or projected DOS.
- No-argument startup continues to prefer a real vasprun.xml; when XML is absent but DOSCAR exists, it loads DOSCAR. With neither file, the normal blank modeling session remains. Explicit/restored input handling is unchanged.

### Verification and limits

- Three focused parser/source tests passed: standalone/case-sensitive-path dispatch without POSCAR/INCAR, selected-file identity and Fermi energy, two spin channels, exclusion of a projected tail, malformed/truncated/inconsistent input rejection, and XML/POSCAR dispatch preservation.
- Actual Linux X11 Frame/startApplet and file-chooser OK-button checks passed for four startup modes: a current directory with XML, explicit DOSCAR, explicit XML, and a DOSCAR-only directory. Repeated transitions through Info, Models, Build and electronic controls restored visible DOS curves. Open loaded both file types from different directories, including a path with spaces; changing systems while DOS remained active updated the data.
- Checked actual numeric energy offsets and different DOS amplitudes to detect stale curves, spin-up/down sign handling and reentry, synthetic two-band DOS+bands mode, widget allocation during resizing and screenshots. Inspected rendered DOS screenshots; inputs/outputs used temporary synthetic files and did not modify user calculations.
- Existing 57 basic tests, all 8 testGtk3 checks, 32 applet startups excluding GLUT, and four blank/explicit-input startup scenarios passed on this Linux device. Python compilation and whitespace checks passed. GTK/GI deprecations and an initial natural-allocation warning were observed; they are not claimed as fixes. These current Linux results do not establish other-platform behavior or erase historical failures on other environments.
- The first end-to-end test exhausted an unbounded GTK event drain and timed out; bounded event batches corrected the fixture. The DOSCAR-only fixture also left Info active when skipping a nonexistent XML input; fixed the test branch before rerunning that mode. Neither fixture issue is claimed as an application fix.
- Tests added: test/testDoscarSystem.py, test/testElectronicDosGtk.py, test/dos_fixtures.py. Real user result files, session serialization, full manual/scientific acceptance, macOS/Windows and standalone GLUT were not validated. No native rebuild or Windows package was produced.

### Documentation and publishing scope

- Updated the operation guide and memory with load/reentry behavior, standalone-DOS limits, Fermi/spin conventions and evidence. Preserved existing INCAR edits, root QR originals and the untracked Fe_single_atom directory; these are not part of this update.

## 中文

### 用户报告与复现的绘图刷新错误

- 用户报告：`p4v &`、`p4v DOSCAR`、`p4v vasprun.xml`首次DOS正常，但切换其他面板再回DOS+bands时空白；File/Open载入DOSCAR或vasprun.xml后也不显示。
- 追踪frame.glade的DOS+bands工具栏 → p4v.startApplet/showApplet → ElectronicApplet的graphwindowapplet.glade → GraphCanvas与GTK3/Cairo适配器；File菜单和Open共用load_system_selected/getSystem及系统激活。
- 真实Frame/startApplet合成数据复现GraphCanvas.updateSize的AttributeError：GTK3 Gdk.Window没有get_size，中断了调度中的DOS重绘。改为读取绘图DrawingArea的实际分配宽高，至少1像素，也适用于尚未realize的窗口；未更换渲染后端或重写面板销毁机制。

### DOSCAR独立载入与总DOS解析

- getSystem原将DOSCAR等所有非XML文件当作PoscarSystemPM。新增按文件名大小写无关识别DOSCAR的DoscarSystemPM，直接读取所选文件、总DOS和头部费米能级；POSCAR／CONTCAR及INCAR可选，不再把DOS数据当原子坐标。
- readDOSCAR按头部NEDOS读取：3列形成一个通道，5列自旋数据分为上下各自能量／密度／积分通道，不把后面的投影DOS块混入TOTAL_DOS。非法头部、截断及列数不一致明确失败，不生成假数据；由读取器打开的文件成功／失败均关闭。
- 保留原始密度数值，ElectronicApplet沿用E−E_Fermi和下自旋绘负值的约定。独立DOSCAR不提供能带本征值或投影DOS。
- 空参数启动仍优先读取实际vasprun.xml，没有XML但有DOSCAR时读取DOSCAR；两者均无时保留正常空白建模。显式／已恢复输入策略不变。
