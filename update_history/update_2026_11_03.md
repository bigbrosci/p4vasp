# 2026-11-03 — macOS startup activation and GTK keyboard input / macOS 启动置前与 GTK 键盘输入

## English

### Report and diagnosis

- The user reported that `p4v` opened behind other applications and Models → gas phase → SMILES would not accept keyboard input on an already installed Mac.
- This checkout uses Python 3.15.2, GTK 3.24 and `GdkQuartzDisplay` on an Intel Mac (Darwin 24.6.0). Desktop GTK initialization succeeded outside the sandbox; sandbox initialization aborted, which is not evidence of an application defect.
- A minimal same-process Cocoa key probe inserted `c` in pure GTK. Adding the existing FLTK `VisCheck()` loop left the focused entry empty. This reproduces event-loop competition rather than an uneditable SMILES field. GTK Quartz needs to translate native key events itself; FLTK's independent dequeue bypassed that translation.

### Changes

- `lib/p4vasp/gtk3/macos.py` configures Quartz event ownership before `Frame.init3d()` initializes FLTK. On macOS with the process-local flag enabled, `src/VisMain.cpp` handles queued native window commands and flushes FLTK drawing, leaving Cocoa dequeueing to GTK. GTK forwards non-GTK events to AppKit/FLTK. Standalone native callers retain their existing loop.
- After startup finishes, the new helper activates the application through typed Objective-C runtime calls and presents the GTK frame once. No PyObjC, AppleScript, Accessibility permission, or persistent always-on-top state is added.
- Traced entry wiring: GTK3 `glade.XML` adapter loads `frame.glade` Models toolbar → `ModelsApplet` → `models.glade` host → `GasPhasePage` → editable `file_dialogs.entry`. No SMILES-specific key interception or disabled initial input was found; no Glade/layout change was needed.
- Added `test/testMacQuartzInput.py`, architecture notes, and updated startup/operation guidance. Native code was rebuilt on this Mac. The pre-existing `odpdom/cODP.py` SWIG-version difference is preserved and excluded from this update.

### Verification and limits

- `install/build-macos-py3.sh`: compiled and linked successfully; desktop GTK/native import check passed. Initial sandbox run compiled/linked but aborted during GTK import; the desktop rerun completed.
- Desktop `testMacQuartzInput.py`: passed actual Cocoa SMILES typing, Backspace, Charge input, application activation, selected-atom native Delete delivery, and input after returning from the native window. The negative `--legacy` control failed as expected with an empty entry. Tests post only to their own windows and avoid unrelated interpreter teardown with `os._exit()`.
- The displayed test window was rendered to `/tmp/p4vasp-mac-focus/gas-phase.png` and visually inspected. Full `P4VASP_INSTALL_PREVIEW=1 bash p4v.sh` startup completed and exited successfully after the existing two-second mapped-window preview.
- Project checks on this Mac: 57 basic tests and 8 GTK tests passed. Applet smoke: 31 passed, 1 failed (DBApplet/Resources), GLUT excluded. Isolated ResourceHub also exited 139 after `PANGO_IS_FC_FONT_MAP` failed in the existing community-font path, which calls PangoFc on macOS's different font backend. This separate Resources issue remains unresolved; the full smoke suite is not clean. Models passed. Logs are under `/tmp/p4vasp-mac-focus/` and are temporary evidence, not shipped artifacts.
- Physical keyboard/input methods, user relaunch confirmation, full manual 3D mouse workflows, SMILES optimization/RDKit, scientific calculations, and other platforms were not validated. A programmatic activation assertion does not prove all macOS Spaces/window-management configurations.

## 中文

### 用户报告与诊断

- 用户报告：已安装的 Mac 输入 `p4v` 后窗口位于其他应用后面；Models → gas phase → SMILES 无法键盘输入。
- 本机为 Intel Mac，Darwin 24.6.0，Python 3.15.2、GTK 3.24、`GdkQuartzDisplay`。桌面环境 GTK 初始化成功；沙箱内初始化退出，不据此判断应用损坏。
- 最小同进程 Cocoa 按键诊断：纯 GTK 能输入 `c`，加入现有 FLTK `VisCheck()` 轮询后，有焦点的输入框仍为空。已复现两套事件循环竞争；SMILES 输入框本身可编辑。GTK Quartz 必须自行翻译原生键盘事件，FLTK 取走事件会绕过该过程。

### 修改

- 新增 `gtk3/macos.py`，在 `Frame.init3d()` 原生初始化前配置 Quartz 事件归属。macOS 启用进程内标记时，`VisMain.cpp` 继续执行原生窗口命令及刷新绘图，由 GTK 取 Cocoa 事件，并把非 GTK 事件转交 AppKit/FLTK；原生独立调用保留原循环。
- 启动完成后，通过带类型签名的 Objective-C runtime 调用激活应用，并将 GTK 主窗口置前一次；不新增 PyObjC、AppleScript、辅助功能权限或永久置顶。
- 已追踪 GTK3 `glade.XML` 适配器加载 `frame.glade` Models 工具栏 → `ModelsApplet` → `models.glade` 宿主 → `GasPhasePage` → `file_dialogs.entry`。未发现 SMILES 专用按键拦截或初始禁用，无需修改 Glade／布局。
- 新增 `testMacQuartzInput.py`，同步架构及启动操作说明。本 Mac 已重编译。已有 `odpdom/cODP.py` 的 SWIG 版本差异保留、不纳入本次更新。

### 验证与边界
